# 📅 План разработки HoneyForge (Хакатон — 7 дней)

## 📌 Расписание по дням

### День 1 (сб) — Фундамент
* **тимлид:** Репозиторий (коллабораторы, ветки, CI). Схемы событий и БД, `docs/API.md`. Каркас `docker-compose` с Nginx и PostgreSQL.
* **Бэкенд:** Ставит окружение. Таблицы (`profiles`, `traps`, `events`, `users`, `audit`) по общей схеме.
* **Иван:** Выбирает движок эмуляции (свой на asyncio или открытый движок) и модель для LLM. Прототип fake-SSH.
* **Миха:** Каркас UI, мок-данные по контракту события, страницы-заглушки.

### День 2 (вс) — Ядро
* **тимлид:** Агент: конфиг, транспорт по TLS, буфер событий. Low-ловушка (баннеры портов).
* **Бэкенд:** Control API: CRUD профилей (FR-C1), регистрация и статусы (FR-C2), логин оператора (FR-C5).
* **Иван:** Medium: fake-SSH (логин-приманка, фейковый shell и FS).
* **Миха:** Экран логина, список ловушек со статусами, конструктор профилей (форма).

### День 3 (пн) — Телеметрия
* **тимлид:** Агент ↔️ центр: выдача конфига (FR-C3), отправка событий, дослылка при обрыве (FR-A4).
* **Бэкенд:** Коллектор телеметрии: приём, нормализация, запись в БД, фильтры (FR-C4).
* **Иван:** Medium: fake-HTTP (админка, ошибки как у настоящего) и fake-БД.
* **Миха:** Лента событий, фильтры, подключение к API вместо моков.

### День 4 (вт) — Realtime
* **тимлид:** WebSocket-поток событий. Первый общий запуск всего стека.
* **Бэкенд:** Журнал аудита, права, стабильность API. Начало оркестратора (FR-C6).
* **Иван:** Honeytokens, фейковые учётки. Подключает эмуляторы к агенту как плагин.
* **Миха:** Dashboard в реальном времени по WebSocket, карточки статусов.

### День 5 (ср) — Маскировка
* **тимлид:** MASK-1…4: неприметный endpoint, mgmt-подсеть, имя процесса и расположение агента. Проверка «атакующим».
* **Бэкенд:** Оркестратор: сборка артефакта (Docker-образ/скрипт) и деплой на хост.
* **Иван:** Анти-фингерпринтинг (MASK-6): тайминги, баннеры. Классификация атак.
* **Миха:** Графики (Chart.js), топ источников, экран деплоя, оформление.

### День 6 (чт) — Бонусы и полировка
* **тимлид:** Интеграционное тестирование, баги, джиттер beacon'ов (MASK-5). **Заморозка фич вечером.**
* **Бэкенд:** Правила-алерты (≥N попыток входа в минуту), экспорт IoC в CSV/STIX.
* **Иван:** Резюме сессии для оператора, скоринг опасности. Автогенерация профиля из описания.
* **Миха:** Подсветка алертов, правки по багам, скриншоты для презентации.

### День 7 (пт) — Демо
* **тимлид:** Репетиция сценария «атака → событие в центре за секунды». README, схемы.
* **Бэкенд:** Фикс багов, чистка данных, резервное копирование БД.
* **Иван:** Подготовка демо-атаки (сканер/брутфорс), последние правки.
* **Миха:** Финальная полировка UI, презентация.

---

## 🚩 Контрольные точки
- **Конец дня 1:** Контракт события и API зафиксирован, у всех работает окружение.
- **Конец дня 3:** Событие из ловушки доходит до БД.
- **Конец дня 4:** Атака видна на дашборде в реальном времени. Это ядро демо, дальше только расширяем.
- **Вечер дня 6:** Заморозка фич, затем только исправления.

## ⚖️ Правила работы
1. Ежедневный созвон на 10 минут и общий запуск стека (`docker compose up`) в конце дня.
2. Ветка на человека, PR в `main` с ревью от соседней роли. Фронтенд и бэкенд ревьюят друг друга по контракту API.
3. Если день 4 срывается, режем бонусы (CSV/STIX, High, mTLS), но **не Must и не маскировку**.

## 🎯 Что покрывают Must и бонусы
- **Must:** `FR-C1…C5`, `FR-A1…A4`, `MASK-1…4`.
- **Бонусы:** `FR-C6`, `FR-C7`, `MASK-5`, `MASK-6`, honeytokens (`FR-A6`). Они реализуются в днях 4–6 и идут по остаточному принципу. 
- *High-interaction (`FR-A5`) и mTLS (`MASK-7`) в плане нет. Берутся только если останется время.*
